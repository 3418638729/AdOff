# 原理与排查

## 一、广告是怎么来的

一个 App 想展示广告，通常不是自己做，而是接入**广告 SDK**：

```
App 启动
  └─ SDK 初始化
       └─ 向 pgdt.gtimg.cn 请求广告素材
            └─ 拿到图片/视频 → 显示在开屏或信息流
```

所以广告能出现，前提是 **SDK 成功请求到了广告服务器**。

## 二、AdOff 拦在哪一层

```
App 启动
  └─ SDK 请求 pgdt.gtimg.cn
       └─ 系统问 DNS：这个域名在哪？
            └─ AdAway 的 VPN 接管了 DNS
                 └─ 查到黑名单 → 回答"没有这个域名"
                      └─ SDK 请求失败，广告位空着
```

AdAway 通过 Android 的 `VpnService` 接口接管整机 DNS，
不需要 root。系统把它的虚拟网卡记为 `tun0`。

**关键判断**：只有 `tun0` 存在，才说明拦截在工作。
AdAway 进程活着、界面显示 18 万条规则，都不代表 VPN 还连着。

## 三、为什么只认 hosts 格式

AdAway 的规则解析器只接受：

```
0.0.0.0 example.com
```

以下格式都会被**静默忽略**（不报错，但规则数是 0）：

- 纯域名列表：`example.com`
- Adblock 语法：`||example.com^`
- easylist 格式

所以 `hosts.py` 统一把 anti-AD 的域名列表转成 `0.0.0.0 域名`。

## 四、为什么文件名是 .log

小米 / HyperOS 的系统文件选择器（SAF）按 MIME 类型过滤，
`.hosts` 和 `.txt` 都不在它认识的可选列表里，只有把文件改成
`.log` 才能在选择器里看到。

文件实际推送到：

```
/sdcard/.xlDownload/anti-ad.log
```

`.xlDownload` 是迅雷下载目录，位于存储根目录，不是 `Download` 里面。

## 五、排查清单

### 1. 先确认 VPN 活着

```bash
adb shell ip addr show | grep tun0
```

应该看到：

```
tun0: <POINTOPOINT,UP,LOWER_UP> ... inet 192.0.2.1/24
```

没有的话：

```bash
adb shell am force-stop org.adaway
adb shell monkey -p org.adaway -c android.intent.category.LAUNCHER 1
```

### 2. 再确认具体域名被拦

```bash
adb shell ping -c 1 gdt.qq.com
```

- `unknown host` → 拦截生效
- 返回 IP → 没拦住

### 3. 查看 AdAway 的实时日志

AdAway 主页 →「显示 DNS 请求记录」。

左侧圆标含义：

| 颜色 | 含义 |
|---|---|
| 红色 ⊘ | 已拦截 |
| 灰色 ⊘ | 未命中名单，正常放行 |

如果广告域名是灰色的，把它加进 `data/sdk-domains.txt`，
然后重新运行 `python adoff.py block --refresh`。

### 4. 规则数对不上

正常情况下应该在 **10 万条以上**。如果显示 0 或几百：

- 本地文件没被读取 → 重新添加来源
- 源格式不对 → 确认用的是 `build/anti-ad.hosts`

## 六、为什么有的广告拦不住

| 情况 | 原因 | 能否解决 |
|---|---|---|
| 广告图还在显示 | 素材已缓存在本地 | 清 App 缓存 |
| 大厂 App 广告 | 自建 HTTPDNS，绕开系统 DNS | 基本无解，靠 Gkd 点击 |
| 京东/天猫广告 | 与业务共用域名 | 拦了会坏功能 |
| 会员/优惠券弹窗 | App 自家推广，不走广告 SDK | 不该拦 |

## 七、保活设置

AdAway 被系统杀掉后，VPN 会断开。建议手动设置：

**小米 / 红米**：

1. 设置 → 应用设置 → 应用管理 → AdAway
2. 自启动 → 打开
3. 省电策略 → 无限制

**通用**：AdOff 已经自动把 AdAway 加进电池优化白名单。
